# 问候语生成

问候语的难点不是词藻，而是**校准**：同一句"新年快乐"，发给三年没联系的前同事和发给昨天刚聊过的室友，得体程度完全不同。写得过热显得虚假，写得过冷显得敷衍。这个 Skill 的作用是先把关系与场合钉住，再落笔。

## 先确认四个变量

动笔前先从用户的请求里读出这四项。它们决定了措辞的全部基调：

| 变量 | 要判断的内容 |
|------|------|
| 关系 | 上级 / 平级同事 / 下属 / 客户或合作方 / 亲友 / 陌生人；以及**亲疏程度**（每天见 vs 久未联系） |
| 场合 | 日常、节日、生日、入职、离职、道谢、道歉、慰问、商务开场、重逢 |
| 渠道 | 邮件、即时消息（微信/Slack）、口头发言、贺卡、公开致辞——渠道决定长度与正式度 |
| 语言与地域 | 中文 / 英文 / 其他；中文还要区分大陆、港台、海外华人的习惯用语 |

**能推断的就推断，不要为了凑齐四项去盘问用户。**"给客户发中秋祝福"已经足够动笔了——客户 + 节日 + 大概率消息或邮件 + 中文。只在缺失项会显著改变结果时才问，而且一次只问最关键的一到两个。典型的必须问的情况：

- 慰问类（丧事、疾病、裁员）——措辞容错极低，且需要知道亲疏与具体情况；
- 用户说了"给领导"但没说是私下消息还是全组可见——公开与私下的分寸差别很大；
- 语言不明且收件人姓名是外文。

## 输出格式

直接给成品，不要前置解释。默认给 **2–3 个版本**，因为问候的合适度高度依赖用户没说出口的关系细节，多个梯度让用户自己挑比反复追问更省事。每个版本标注定位：

```
**偏正式**
<正文>

**中性**
<正文>

**偏亲近**
<正文>
```

版本之间要有**真实差异**，不是同义词替换。差异应体现在称呼、是否寒暄、是否提具体事、是否带请求上。如果场合本身只容得下一种分寸（如上级的丧事慰问），就只给一个版本，并说明为什么不给梯度。

需要填空的地方用 `[方括号]` 明确标出（如 `[姓名]`、`[项目名]`），不要用"某某"或编造具体信息。如果用户给了姓名、公司、项目名，直接填进去。

结尾可以附**一行**使用提示，仅在确有必要时——例如"发邮件建议把主题写成……"或"若对方已回复过，删掉第一句寒暄"。不要写成使用说明书。

## 让问候不像模板

模板化的问候没有作用，收件人一眼就能看出来，反而不如不发。三个可操作的做法：

1. **锚定一个具体的东西。** 一句"上次你提的那个缓存方案后来落地了吗"胜过三句"希望一切顺利"。用户给了上下文就用起来；没给，就在版本里留 `[具体事项]` 的位置提示用户填，而不是用空泛的祝愿把它填满。
2. **删掉能删的套话。**"在此，我谨代表……向您致以最诚挚的问候"在多数渠道里是噪音。正式不等于冗长；商务邮件的正式感靠称呼、结构和用词准确度撑起来，不靠堆砌敬语。
3. **别越过关系的边界。** 平级同事之间说"辛苦了"自然，对客户说就有居高临下之嫌；对久未联系的人一上来热络寒暄会让人尴尬，坦承"好久没联系"反而得体。

## 中英文的差异不是翻译问题

写英文问候时不要先想中文再译。两种语言的问候在结构上就不同：

- 中文邮件常见"见字如面""顺祝商祺"这类程式，英文对应的是 `Hope this finds you well` / `Best regards`，但英文商务写作近年更倾向直接进入正题，过度寒暄反而显得不专业；
- 中文习惯先铺垫后说事，英文习惯先说事；
- 中文的敬语依靠词汇（贵公司、您、拜读），英文依靠句式（`Would you mind…` vs `Can you…`）和称呼（`Dear Dr. Chen` vs `Hi Ming`）。

要求双语时，两个版本都要在各自语言里读起来自然，允许信息不完全对等。

## 需要格外小心的场合

- **慰问与哀悼**：不要说"我理解你的感受"或劝人节哀振作；有效的慰问是承认损失、提供具体帮助、不索取回复。避免任何祝福语气的词。
- **节日的文化边界**：不确定对方是否过这个节日时，用中性表达（`Happy Holidays`、"祝顺利"）而不是默认某个宗教节日；斋月、复活节、农历新年都有各自的问候惯例和忌讳。
- **道歉与致谢混在一起**：用户说"给客户发个问候顺便道歉"时，把道歉写在前面且不要用问候稀释它——先致歉、承担、给方案，问候只是包装。
- **跨层级的公开发言**：全员可见的问候会被当成表态，避免只点名个别人，避免承诺资源。

## 示例

**示例 1**
输入：帮我给合作了两年的供应商写个春节祝福，微信发
输出：
```
**偏正式**
[称呼]，新春快乐！过去一年多谢您和团队在 [具体事项] 上的配合，节后再约时间聊聊今年的安排。祝阖家安康。

**中性**
[称呼]，春节快乐！这一年合作得很顺，辛苦了。节后联系，祝新年顺利。
```

**示例 2**
输入：新同事下周入职，我是他 mentor，写个欢迎消息
输出：
```
**中性**
[姓名] 你好，欢迎加入！我是 [自己的名字]，接下来会当你的 mentor。入职前不用做任何准备，第一周我们主要一起过一遍 [团队/系统名] 的结构。有任何问题随时找我，包括很小的问题。

**偏亲近**
[姓名]，欢迎！我是 [自己的名字]，你的 mentor。第一周别有压力，环境和代码慢慢摸，不懂就问我——问得越多我越省心。到时候见！
```
注意第二个版本用"我越省心"消解新人的顾虑，比"欢迎提问"更能真正降低对方的开口门槛。
